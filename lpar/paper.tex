\begin{abstract}
We present a neural system for generating intermediate lemmas
(cut formulas) that speed up automated theorem provers on large
mathematical libraries.  Given a first-order CNF problem, a
heterogeneous graph neural network encoder represents the clause
structure, and a Transformer decoder autoregressively generates
candidate lemmas with arity-constrained decoding.  Using the Gentzen
cut rule, each candidate is evaluated by checking that both the
problem with the lemma and its negation are provable, measuring proof
search savings as the ratio of combined effort to the baseline.  We
create large-scale datasets from the \Mizar Mathematical Library using
both the \Eprover and \Vampire provers.  For \Vampire, we obtain
196\,199 useful training examples from 2.47M evaluated pairs across
34\,182 problems.  On \Eprover, an ensemble of 15~model configurations
helps on 127 out of 187 provable test problems (67.9\%), with
individual speedups exceeding $196\times$.  Most notably,
conjectures trained on \Eprover data transfer to \Vampire, helping
prove \textbf{582 previously unsolved} \Mizar problems (442 of which
were never solved by any ATP) and speed up 2\,236 others.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Automated theorem provers (ATPs) such as \Eprover~\cite{Schulz2002}
and \Vampire~\cite{Kovacs2013} are powerful tools for establishing
validity of first-order conjectures.  However, proof search can grow
exponentially with the number of input clauses, and many problems
remain beyond reach even with sophisticated heuristics.

A classical technique for reducing proof search is the \emph{cut rule}
(Gentzen, 1935): for any formula~$L$, if both $P \cup \{L\}$ and $P
\cup \{\neg L\}$ are unsatisfiable, then $P$ itself is unsatisfiable.
Crucially, $L$ need not be ``true'' in any semantic sense---it is a
case split that decomposes one hard proof into two easier subproofs.
A well-chosen intermediate lemma can dramatically reduce total search
effort, but finding such lemmas automatically is challenging.

We propose a neural approach to conjecture generation.  A
heterogeneous graph neural network (GNN) encodes the structure of the
input CNF problem---its clauses, literals, symbols, terms, and
variables---and a Transformer decoder generates candidate lemmas
autoregressively, using a pointer mechanism to select symbols from the
input and arity-constrained decoding to ensure syntactic validity.  We
train on examples where proof lemmas extracted from successful ATP
runs provide measurable speedups, and at inference time generate
diverse candidates verified by the prover.

We create two datasets from the \Mizar Mathematical Library
(\MML)~\cite{Grabowski2010}: a development dataset using \Eprover
(3\,161 problems, 122K examples) and a large-scale dataset using
\Vampire with neural clause selection~\cite{Suda2025} (34\,182
problems, 196K useful examples from 2.47M evaluated pairs).  On the
\Eprover dataset, we train and evaluate multiple model configurations,
demonstrating strong complementarity: while the best single model
helps on 96 test problems (51.3\% of provable), an ensemble of
13~configurations reaches 125 problems (66.8\%).

Our contributions are:
\begin{enumerate}
\item A heterogeneous GNN encoder with five node types and 16~edge
  types, using edge-aware convolutions for positional information.
\item An autoregressive Transformer decoder with arity-constrained
  generation, pointer-based symbol selection, and role-aware masking.
\item Two large-scale cut-formula datasets for \Mizar, with the
  \Vampire dataset providing 196K useful examples---over 12$\times$
  the \Eprover dataset.
\item Comprehensive evaluation with complementarity analysis,
  budget-optimal allocation across model variants, and rank analysis
  showing where useful conjectures appear.
\end{enumerate}

\section{Datasets}
\label{sec:dataset}

We create training data by evaluating intermediate lemmas extracted
from successful proofs on the \MML.  The general procedure is: (1)
solve CNF problems with an ATP, (2) extract proof lemmas, (3) for each
(problem, lemma) pair, run the cut evaluation (Sec.~\ref{sec:cut}),
and (4) retain pairs where the combined cost of the two subproofs is
less than the baseline.

\subsection{The Cut Rule and Evaluation}
\label{sec:cut}

For a CNF problem~$P$ and a candidate lemma~$L$, we evaluate the cut
rule by running the ATP twice:
\begin{itemize}
\item $P \cup \{L\}$: the problem with $L$ as an extra axiom (P1),
\item $P \cup \{\neg L\}$: the problem with the negation of $L$ (P2).
\end{itemize}
If both succeed, the \emph{speedup ratio} is $r = (C_1 + C_2) / C_0$,
where $C_0$ is the baseline cost and $C_1, C_2$ are the costs of the
two subproofs.  A ratio $r < 1$ indicates a genuine speedup.  The cost
metric is processed clauses for \Eprover and instructions burned for
\Vampire.

\subsection{Speculative Lemma Use via AVATAR Claims}
\label{sec:avatar}

A key challenge in using generated conjectures is that each lemma~$L$
must itself be proved from the problem's axioms before it can be
soundly used.  Running two separate proofs ($P \cup \{L\}$ and
$P \cup \{\neg L\}$) doubles the evaluation cost.
\Vampire's AVATAR architecture~\cite{Kovacs2013,Voronkov2014}
provides an elegant solution through \emph{claim
formulas}~\cite{Einarsdottir2024}.

AVATAR maintains a propositional abstraction layer that tracks
which clauses depend on which splitting assumptions.  When a
candidate lemma~$L$ is introduced as a \emph{claim}, \Vampire
internally creates a fresh propositional symbol~$p$ and adds the
equivalence $p \leftrightarrow L$ as an axiom.  After clausification,
AVATAR recognizes $p$ and $\neg p$ as complementary components and
explores two scenarios in an interleaved fashion:
\begin{itemize}
\item Under assumption~$p$: the prover works with $L$ as an axiom,
  attempting to prove the main conjecture using the lemma.
\item Under assumption~$\neg p$: the prover works with $\neg L$,
  effectively trying to prove the lemma itself.
\end{itemize}
The underlying SAT solver orchestrates which scenario to explore,
and declares the proof complete when both directions have been
resolved.  Cyclic reasoning is automatically avoided because $p$
and $\neg p$ are treated as mutually exclusive assumptions.

This mechanism has three practical advantages for our setting:
\begin{enumerate}
\item \textbf{Single proof attempt:} Both $P \cup \{L\}$ and
  $P \cup \{\neg L\}$ are handled in one \Vampire invocation,
  halving the evaluation cost.
\item \textbf{Shared work:} Clauses derived independently of
  the claim (from axioms alone) are reused across both scenarios,
  avoiding redundant computation.
\item \textbf{Multiple claims:} Several generated conjectures can
  be introduced as claims simultaneously, allowing AVATAR to
  explore the power set of lemma combinations.  The SAT solver
  finds which subset suffices.
\end{enumerate}

In our experiments (Sec.~\ref{sec:transfer}), we introduce each
generated conjecture as a claim formula, allowing \Vampire to
speculatively use it while simultaneously verifying it.  This is
implemented via the TPTP \texttt{claim} role, requiring no
modification to \Vampire beyond the existing parser
support~\cite{Einarsdottir2024}.

\subsection{Problem Corpus}

The \MML contains over 60\,000 formalized mathematical theorems.  We
export these as first-order problems in TPTP
format~\cite{Sutcliffe2009}.  Three problem versions are used, differing
in premise selection:

\begin{enumerate}
\item \textbf{Post-proof minimized (E prover dataset):}
  Each problem contains only the axioms that were used in a successful
  proof, yielding very small problems (${\sim}45$~clauses on average).
  Useful for initial method development but unrealistic for deployment,
  since the ``right'' premises are not known in advance.

\item \textbf{Full axiom set (Vampire dataset):}
  The 57\,880 CNF problems include the full \Mizar background theory,
  averaging ${\sim}430$~clauses.  This is a more realistic but
  computationally demanding setting.

\item \textbf{Premise-selected (Mizar60 dataset):}
  Using the Mizar60 premise selection data~\cite{KaliszykU2015}, we
  construct 55\,832 FOF problems where each theorem is paired with
  its minimum sufficient premise set (the smallest set of axioms from
  which the theorem was proved).  These problems have a median of
  13~premises (mean 25.4, range 0--478), providing a middle ground:
  the problems are realistically sized for ATP evaluation while
  being much smaller than the full axiom set.
  Table~\ref{tab:premise-dist} shows the premise count distribution.
\end{enumerate}

\subsection{E Prover Dataset}
\label{sec:eprover-data}

We use \Eprover version 2.6 (Floral Guranse)~\cite{Schulz2002} with
\texttt{--auto} mode and a 10-second wall-clock timeout on post-proof
minimized CNF problems.  From 3\,161 problems, \Eprover solves 1\,888.
For each solved problem, we extract intermediate clauses from the proof
and evaluate them as cuts using the same prover and timeout.  The cut
evaluation runs on 64 parallel workers.
This yields 122\,356 (problem, lemma) pairs.

We split by problem into 2\,239 / 279 / 279 (train / val / test).
Of the 187 provable test problems, our models help on up to 125
(66.8\%) using an ensemble of 13~configurations
(Sec.~\ref{sec:eprover-results}).

\subsection{Vampire Dataset}
\label{sec:vampire-data}

We run \Vampire with neural clause selection~\cite{Suda2025} on
the premise-selected Mizar60 CNF problems using a single non-AVATAR
strategy with a 50~billion instruction limit (approximately 58
minutes of wall-clock time on 64 cores).  Out of 55\,832 problems,
\Vampire solves \textbf{34\,080} (61.0\%).  This is comparable to
the 34\,182 solved on the full-axiom CNF corpus (59.1\%), confirming
that the premise-selected problems retain the essential difficulty
while being much smaller.

For each solved problem, \Vampire produces proof lemmas in
first-order (FOF) format.  The lemmas are normalized using
\texttt{tptp4X}~\cite{Sutcliffe2009} (with \texttt{-u machine}

references).  All resulting lemmas are universally quantified
disjunctions (no existential quantifiers, implications, or
conjunctions), making conversion to CNF trivial.

\section{Architecture}
\label{sec:arch}

\subsection{Heterogeneous GNN Encoder}

The input CNF problem is represented as a heterogeneous graph with
five node types---\emph{clause}, \emph{literal}, \emph{symbol},
\emph{term}, and \emph{variable}---and 16~directed edge types
capturing the problem structure (e.g., \texttt{clause\_has\_lit},
\texttt{literal\_has\_arg}, \texttt{term\_has\_subterm}, and their
reverses).  Each node receives a learned type embedding as its initial
feature.

We apply $L=4$ layers of message passing.  Edges carrying positional
information (argument positions in terms and literals) use GINEConv
(edge-aware graph isomorphism network~\cite{Hu2020}), while
non-positional edges use SAGEConv~\cite{Hamilton2017}.  After message
passing, the graph pooling produces a global context vector via mean
aggregation over symbol nodes.

\paragraph{Symbol-independent design.}
A crucial design choice is that the model is fundamentally
\emph{symbol-independent}: generated clauses are constructed by
\emph{pointing} to symbol nodes in the input graph (see below), not
by selecting from a fixed output vocabulary.  This means the model can
generate conjectures for problems containing symbols it has never seen
during training---the GNN encodes each symbol's structural role
(arity, predicate vs.\ function, which clauses and terms it appears
in) regardless of its name.

Optionally, \emph{named symbol embeddings} add a learnable vector per
known Mizar symbol name (${\sim}3\,097$ symbols), summed into the
GNN's symbol node features before message passing.  This allows the
model to recognize recurring symbols across problems (e.g., ``this is
\texttt{r2\_hidden}, which typically behaves like set membership'').
Unknown symbols simply receive a shared UNK embedding and still
function correctly through the pointer mechanism and GNN-propagated
structural features.

\subsection{Autoregressive Transformer Decoder}

The decoder generates a clause as a sequence of \emph{actions}, each
paired with an \emph{argument}.  There are seven action types:
\textsc{NewLitPos} and \textsc{NewLitNeg} (start a positive/negative
literal), \textsc{Pred} (select predicate symbol), \textsc{ArgVar}
(select variable), \textsc{ArgFunc} (select function symbol and push
arity obligation), \textsc{EndArgs} (close current term), and
\textsc{EndClause} (finish generation).

The decoder is a standard Transformer with $d$-dimensional
cross-attention to the encoded graph.  At each step, it produces
three outputs:
\begin{enumerate}
\item An \emph{action distribution} over the 7~types, masked by
  role constraints (e.g., after \textsc{NewLitPos}, only
  \textsc{Pred} is allowed).
\item A \emph{pointer distribution} over the input graph's symbol
  nodes for \textsc{Pred}/\textsc{ArgFunc} actions, computed via
  dot-product attention between the decoder state and the GNN's
  symbol node embeddings.  This is the key mechanism enabling
  symbol independence: the model selects symbols by their
  \emph{learned graph representations}, not by name.  Role-aware
  masking ensures predicates are only pointed to by \textsc{Pred}
  and functions by \textsc{ArgFunc}.
\item A \emph{variable distribution} over $V_{\max}=20$ variable
  slots for \textsc{ArgVar} actions.
\end{enumerate}

At inference, we use KV caching for efficient autoregressive
generation.

\subsection{Arity-Constrained Decoding}

A key challenge is syntactic validity: generated clauses must have
correct argument counts for each symbol.  We maintain an arity
obligation stack during generation.  When a symbol with arity~$k$ is
selected (via \textsc{Pred} or \textsc{ArgFunc}), $k$ arguments are
required before \textsc{EndArgs} is allowed.  This state machine
modifies the action logits at each step, setting disallowed actions to
$-\infty$ before sampling.

\subsection{Model Variants}

We experiment with three decoder architectures sharing the same GNN
encoder:
\begin{itemize}
\item \textbf{Plan A (Transformer)}: the primary architecture
  described above.
\item \textbf{Plan C (Conditional VAE)}: adds a variational
  autoencoder that encodes the target clause into a latent code,
  concatenated with the graph encoding.  At inference, latent codes
  are sampled from the prior, providing a natural source of diversity.
\item \textbf{Plan D (SSM)}: replaces the Transformer with a
  state-space model (Mamba-style~\cite{Gu2024}), using gated linear
  fusion instead of cross-attention.
\end{itemize}

\section{Training}
\label{sec:training}

The loss is a weighted sum of three cross-entropy terms: action
prediction, pointer prediction (for symbol selection), and variable
prediction.  Pointer and variable losses use \texttt{ignore\_index}
for steps where those outputs are irrelevant (e.g., variable loss is
ignored for non-\textsc{ArgVar} steps).

Each sample is weighted by $w = 1/(1 + r)$ where $r$ is the speedup
ratio, so that higher-speedup examples contribute more.  To address
data imbalance across problems, each problem's samples are normalized
so that all problems contribute equally to the epoch loss.

\paragraph{Ratio threshold for training.}
An additional filtering parameter is $r_{\max}$: examples with ratio
above this threshold are excluded from training.  Using $r_{\max} =
0.5$ (only $\geq 2\times$ speedups) yields 66K examples from 1\,645
problems for the \Vampire dataset---a cleaner training signal but
fewer problems for generalization.  Using $r_{\max} = 1.0$ (all
useful examples) yields 196K examples from 3\,591 problems.  We use
$r_{\max} = 1.0$ with the quality weighting handling the distinction:
the loss on a marginal $r = 0.95$ example is weighted at $w = 0.51$
vs.\ $w = 0.91$ for a strong $r = 0.1$ example, so the model focuses
on high-quality cuts without sacrificing problem coverage.

We use AdamW with cosine learning rate scheduling and mixed precision
training (AMP with \texttt{float16} on A100 GPUs) for ${\sim}1.5\times$
GPU throughput.

\paragraph{Validation methodology.}
An early version of the precompute cache used shared filenames for
train and validation samples (\texttt{sample\_0.pt}, etc.), causing
the validation set to silently load training samples.  This produced
artificially low validation losses (training data evaluated with
dropout disabled).  The bug was discovered during the Vampire
scaling work and confirmed by comparing cached validation samples
against freshly computed ones.

With corrected validation, we retrained the $d{=}128$ \Eprover model
(Table~\ref{tab:eprover-valloss}).  The true validation loss curve
reveals severe overfitting: best val is 2.43 at epoch~22, rising to
3.85 by epoch~100.  The conjectures in Sec.~\ref{sec:transfer} were
generated by the $d{=}256$ model (\texttt{af6\_a\_named\_big},
epoch~100), which likely overfits even more due to its larger
capacity.  The $d{=}128$ curve provides a lower bound on the
overfitting severity.

We use a 3\,000-node limit for \Vampire training, balancing coverage
(63\% of useful problems, ${\sim}101$K training samples) against
computational cost.  The largest \Vampire graphs (3\,000--5\,000
nodes) cause GPU memory spikes under fixed-size batching due to the
heterogeneous GNN's per-edge-type convolutions (4~layers $\times$
16~edge types = 64 convolution operations per forward pass).

\paragraph{Size-aware batching.}
To handle the high variance in graph sizes (100--3\,000 nodes), we
replace fixed sample-count batching with a \emph{size-aware batch
sampler} that caps the total node count per batch (default:
100\,000).  Samples are sorted by graph size and greedily packed: a
batch of small graphs may contain 100+ samples, while a batch of
large graphs may contain only 10.  This bounds peak GPU memory
regardless of the graph size distribution.  The training loss uses
weighted mean reduction (dividing by total token count, not batch
size), making it invariant to variable batch sizes.

\paragraph{Scalable data loading.}
The \Vampire dataset's 101K training samples with graphs averaging
${\sim}2\,000$ nodes present a data-loading challenge.  Full
precomputation of all sample graphs into RAM requires ${\sim}15$GB
and is parallelized across 8 threads (${\sim}10$ minutes on first
run).  The precomputed data is saved as a single file for instant
loading on subsequent runs (${\sim}2$ minutes).

During training, the custom collation function uses PyG's
\texttt{exclude\_keys} mechanism to batch graph structures without
copying per-sample target tensors, avoiding the overhead of
deep-cloning large heterogeneous graphs.  Target sequences are
extracted, padded, and stacked separately.  Multiple persistent
DataLoader workers (8 processes) overlap the remaining CPU work
(graph collation, tensor concatenation) with GPU computation.  With
these optimizations and mixed-precision training, we achieve
${\sim}60$--$90\%$ GPU utilization on A100, at ${\sim}7$ minutes
per epoch for the 101K-sample \Vampire training set.

\paragraph{Training configurations.}
For \Eprover, we train with $d \in \{128, 256, 512, 1024\}$,
batch sizes 16--64, and up to 200 epochs.
For the initial \Vampire experiments, we use $d = 128$ (4M
parameters) with mixed-precision training (AMP) on A100 GPUs.
We plan to scale to $d = 256$ once the data pipeline is validated.

\subsection{Experimental Setup}

We train 15~model configurations varying hidden dimension ($d \in
\{256, 512, 1024\}$), decoder variant (A, C, D), named symbol
embeddings (on/off), and sampling parameters.  For each configuration,
we generate 40--80 conjectures per problem using nucleus sampling with
varying temperature ($T \in \{1.0, 1.2, 1.5\}$), top-$k$ ($\in
\{10, 15, 25\}$), and top-$p$ ($\in \{0.9, 0.95, 0.98\}$).

Each generated conjecture is evaluated by running \Eprover 2.6 with a
2-second timeout for both $P \cup \{L\}$ and $P \cup \{\neg L\}$,
using 64 parallel workers.
The test set contains 279 problems, of which 187 are provable by
\Eprover in the baseline (10-second timeout).

\subsection{Per-Method Results}

consistently outperforms precise sampling in problem coverage, though
at a slightly higher average ratio.  Interestingly, the $d{=}1024$

higher-quality individual conjectures (lower average ratio), it covers
fewer problems.  The $d{=}256$ model's advantage comes from faster
iteration and greater diversity at the same compute budget.

neural conjecture generation can find cut formulas that dramatically
reduce proof search in problems that are very expensive for the
baseline prover.

\section{Cross-Prover Transfer: E-Trained Conjectures for Vampire}
\label{sec:transfer}

A key question is whether conjectures learned from one prover's
proof lemmas transfer to another prover.  We test this by applying
the \Eprover-trained model (\texttt{af6\_a\_named\_big}, $d=256$,
named embeddings) to generate conjectures for the Mizar60
premise-selected CNF problems, and evaluating them with \Vampire.

\subsection{Experimental Setup}

We select 11\,900 problems for generation: all 14\,328 unsolved
problems plus 3\,614 hard solved problems ($\geq 2000$M instructions),
filtered to $\leq 1500$ graph nodes (matching the \Eprover training
setting).  For each problem, the model generates 42 conjectures
with diverse sampling ($T{=}1.2$, top-$k{=}15$, top-$p{=}0.95$),
producing 517\,435 conjectures with 98.9\% syntactic validity.

Conjectures are evaluated using \Vampire with AVATAR
splitting~\cite{Kovacs2013}, which tests both $P \cup \{L\}$ and
$P \cup \{\neg L\}$ simultaneously by treating $L$ as a claim
formula.  This halves the evaluation cost compared to separate
P1/P2 runs.  \Vampire uses a neural guidance model trained for
AVATAR on the minimized 55K Mizar60 problems; notably, this
AVATAR-guided baseline (without any generated conjectures) already
solves additional hard problems that the non-AVATAR single strategy
could not.  The instruction limit is 100\,000M (with a 30-second
timeout).

The results demonstrate strong cross-prover transfer:

\paragraph{Baseline.}
Without any generated conjectures, \Vampire with Avatar splitting
and a neural clause guidance model (trained on the minimized Mizar60
problems) proves 3\,738 out of 11\,881 evaluated problems (31.5\%)
within the 100\,000M instruction limit.  Of these, 620 are from the
``minsub'' set of hard problems never previously solved by any ATP.

\paragraph{Newly proved problems.}
With generated conjectures, \textbf{582 previously unproved problems}
are additionally solved, bringing the total to 4\,320 (36.4\%)---a
relative improvement of 15.6\%.  Of these 582, \textbf{442} (76\%)
come from the minsub set, increasing the number of hard problems
solved from 620 to 1\,062---a 71\% improvement on the hardest
problems.  The total number of minsub problems proved (baseline +
conjectures) thus nearly doubles.

\paragraph{Speedups on solved problems.}
For the 1\,599 already-solved problems that benefit, the mean ratio
is 0.610 (39\% reduction in proof search effort) and the median is
0.683.  The largest speedup exceeds $118\times$: \texttt{t1\_diff\_3}
is solved in 844M instructions with the conjecture vs.\ 100\,000M+
baseline.

\paragraph{Rank distribution.}
The first useful conjecture appears at median rank 3 (mean 7.6),
confirming that even a small number of generated conjectures per
problem is effective.  The useful conjectures are distributed
roughly uniformly across ranks 1--42, suggesting that diverse
sampling contributes at every position.

\paragraph{Discussion.}
The cross-prover transfer is notable because the model was trained
exclusively on \Eprover proof lemmas from post-proof minimized
problems, yet produces useful conjectures for \Vampire on
premise-selected problems with different clause structure and size.
The symbol-independent pointer mechanism (Sec.~\ref{sec:arch})
enables this transfer: the model learns structural patterns of
useful cut formulas, not prover-specific heuristics.

\subsection{Iterative Retraining}

The 24\,025 useful examples from this evaluation provide training
data for the next iteration of the conjecture generation loop.
We explore three retraining strategies:

\paragraph{From scratch on transfer data only.}
Training $d{=}256$ on only the 19K transfer examples (1\,788
problems) leads to rapid overfitting: the training loss reaches
0.85 while validation loss plateaus at 1.87 after epoch~31 and
rises thereafter (Table~\ref{tab:retrain}).  The model has 15M
parameters for only 19K training examples---a 788:1 parameter-to-sample
ratio.

\paragraph{Fine-tuning from E checkpoint.}
Initializing from the \Eprover-trained weights and fine-tuning on
the transfer data produces much better initial val loss (1.76 at
epoch~1 vs.\ 3.49 from scratch) and reaches a best val of 1.26 at
epoch~17 (vs.\ 1.87 at epoch~31 from scratch).  The model retains
structural knowledge of clause patterns from \Eprover training.
However, overfitting still occurs: by epoch~120 the gap between
train (0.82) and val (1.27) is significant, and val loss starts
rising after epoch~117.

\paragraph{Combined E + transfer data.}
The most effective strategy combines the original \Eprover training
data with the \Vampire transfer data.  The \Eprover data contains
122K (problem, lemma) pairs from 3\,161 post-proof minimized
problems; filtered at $r \leq 0.9$, this yields 35K high-quality
examples.  The transfer data contributes 24K examples from 2\,236
premise-selected problems.  Since 191 problem names overlap between
the two corpora (same \Mizar theorems, different premise sets), we
prefix the transfer problem names to keep them distinct.
A combined symlink directory provides a unified \texttt{problems\_dir}
pointing to both the \Eprover and Mizar60 CNF problem files.

The resulting dataset has 59K training examples across 3\,902
problems (after ${\leq}1500$ node filtering) and 5\,598 validation
examples across 492 problems---roughly balanced between the two
data sources.  This provides sufficient data for $d{=}256$ training
without severe overfitting, while incorporating the \Vampire-specific
patterns learned from the transfer evaluation.

\section{Related Work}
\label{sec:related}

\paragraph{Cut introduction in ATPs.}
The idea of introducing lemmas to shorten proofs has a long
history~\cite{Gentzen1935}.  In the ATP context, Hetzl et
al.~\cite{Hetzl2014} study cut introduction from a proof-theoretic
perspective.  The key difference in our approach is that we
\emph{generate} candidate cuts neurally, rather than extracting them
from existing proofs.

\paragraph{Neural theorem proving.}
Machine learning has been applied to premise selection~\cite{KaliszykU2015},
proof guidance~\cite{Loos2017,Jakubuv2019,Suda2021,ChvalovskyKPU2023},
and tactic prediction for interactive theorem
provers~\cite{Yang2019,Polu2020}.
Our work is complementary: rather than guiding the proof search, we
generate auxiliary formulas that restructure the problem.

\paragraph{Lemma generation.}
Most closely related is work on neural lemma
generation~\cite{WuJiangCunha2021}, which generates lemmas for
interactive provers.  Our approach differs in targeting first-order
ATPs with the cut rule, using a graph-structured encoder, and
evaluating on a much larger scale with rigorous prover-based
verification.  Gauthier~\cite{Gauthier2021} explores reinforcement
learning for cut introduction in tableaux provers.

\section{Conclusion}
\label{sec:conclusion}

We have presented a neural system for generating intermediate lemmas
that speed up automated theorem provers.

The most striking result is \textbf{cross-prover transfer}: a model
trained exclusively on \Eprover proof lemmas generates conjectures
that help \Vampire prove \textbf{582 previously unsolved problems}
(442 never solved by any ATP) and speed up 2\,236 others.
This suggests that useful cut formulas have structural properties
that generalize across provers.

On the \Eprover \Mizar
dataset, our ensemble of model variants helps on 66.8\% of provable
test problems, with individual speedups exceeding $196\times$.  The
strong complementarity across decoder variants (Transformer, CVAE,
SSM) and sampling strategies suggests that diverse generation is at
least as important as model quality for maximizing coverage.

We have also constructed a substantially larger \Vampire dataset
(196K useful examples from 34K problems, $12\times$ the \Eprover
data), which we expect to significantly improve model quality. The
\Vampire problems are ${\sim}10\times$ larger (full axiom
set vs.\ post-proof minimized), presenting both a challenge for the GNN
encoder and an opportunity for the model to learn to identify relevant
structure in larger contexts.

Future directions include: (1) training on the full \Vampire dataset
and evaluating the resulting conjectures with \Vampire, (2)~iterative
conjecture generation (using generated conjectures to create further
training data), (3)~teacher-forced log-probability scoring to replace
the current heuristic ranking, and (4)~data augmentation through
literal order permutation.
